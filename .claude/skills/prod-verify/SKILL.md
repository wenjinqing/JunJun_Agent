# 生产验证

## 流程

1. **前置**：确认已重启加载新代码（restart-deploy skill），
   配置项已同步到 `config/bot_config.toml`（example 只是模板）。
2. **逐项验收**：按 `docs/生产验证清单_<日期>.md` 的操作/预期/观察/通过四段式执行；
   新功能上线时在清单里**追加新条目**（操作可复现、预期可观察）。
3. **观察渠道**：Langfuse trace（决策链）、WebUI 任务面板（后台 job）、
   logs/（插件与网关日志）、生产库只读查询（订阅/提醒落库）。
4. **沉淀**：问题与根因记 `docs/踩坑清单与常见Bug.md`；
   验收结果回写清单对应条目；重大事项更新 `docs/回归记录.md`。

## 观察期纪律（路线图 Phase 0 模式）

- 每个新功能先确认**关闭开关**存在（配置项），出问题能一键回退再观察。
- 灰度顺序：管理员私聊 → 单群 → 全量（intention 等主动行为的既定路径）。
- 观察期重点指标（按 2026-08 定）：
  - echo guard 误伤率（正常回复被判复读而沉默的次数）
  - 心情流转是否自然（不再卡单一情绪）
  - send-retry 是否双发（历史确认免重发的日志行 `（历史确认免重发）`）
  - 各口吻链路是否一个声音（persona_brief 生效）
- 生产库只读；任何验证需要写数据时用测试库或在测试群进行。
