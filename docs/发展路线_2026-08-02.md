## P5 感知收尾与轻装（1~2 周）

> 目的：吃掉最后一个主流内容平台，同时给决策层减负——工具越绑越多，
> Qwen 的选择压力和 token 成本都在涨。

### P5-1 抖音/小红书内容理解 ✅ 2026-08-03（抖音 SSR+深看完成；小红书零需求证据暂缓）
- **现状**：群友发抖音/小红书链接只有 link_preview 的标题，经常解析不出。
  B站已有三件套（快看 content.py / 深看 watch.py / 分享拦截），模式成熟可复制。
- **方案**：复用 bilibili `content.py` 骨架——分享拦截器预热点开 → 无水印解析
  （aweme detail API 或第三方解析）→ 文案+BGM+热评 → utils 模型摘要注入
  「群里最近分享的抖音」块；问内容走 `douyin_summary` 工具。深看（无字幕视频）
  直接复用 `video_watch` job（下载→ASR→关键帧，平台无关）。
- **触点**：`junjun_skills/plugins/douyin/`（新建，对标 bilibili 插件结构）、
  `agent.py` 拦截器、`registry.py` 关键词钉
- **可能遇到的问题**：
  - **风控远严于 B站**：X-Bogus/msToken 签名是逆向活，随时失效；第三方解析站
    稳定性差且有跑路风险。对策：多解析源 fallback 链 + 失败静默降级为
    link_preview，绝不让解析失败影响正常回复
  - 小红书图文笔记与视频笔记结构不同，需分开处理
  - 短链（v.douyin.com）先 302 展开，注意超时
- **验收**：群里发抖音链接 → 下一轮上下文出现内容摘要；问「这视频讲了啥」
  能答；解析全挂时回复不受影响。
- **工作量**：1.5 天 | **风险**：中（外部依赖不可控）

### P5-2 意图驱动的动态工具子集（CORE 瘦身） ✅ 2026-08-03（代码落地；token/缓存验收待生产实测）
- **现状**：25+ 工具全量绑定，schema 吃掉大量 prompt token；工具越多模型越容易
  选错/幻觉参数。`_TOPIC_KEYWORDS` 钉工具已是雏形。
- **方案**：三层工具集——CORE（回复/表情/记忆/不回复，≤8 个常驻）+
  TOPIC（关键词命中挂载，现有机制）+ INTENT（规则/小模型预判：检测到
  「调研」「订阅」「语音」等意图时挂载对应工具组）。工具分组元数据进注册表。
- **触点**：`junjun_skills/registry.py`、`junjun_agent/agent.py`
- **可能遇到的问题**：
  - **prompt 缓存破坏**：工具列表随消息变化会让前缀缓存失效，token 成本
    不降反升。对策：工具子集**桶化**（固定几种组合 + 稳定排序），
    同桶复用缓存；上线前用 Langfuse 对比 cache_read 命中率
  - **漏绑**：意图预判漏了 → 该用的工具没绑 → 模型只能说「做不到」。
    对策：模型显式请求未绑定工具时（意图规则兜底），下一轮全绑重试
  - 规则维护成本：新插件要登记分组，加进插件开发模板
- **验收**：日常闲聊轮 input token 下降 ≥30%；工具调用成功率不降；
  Langfuse cache_read 命中率不降。
- **工作量**：2 天 | **风险**：中（缓存与漏绑要实测调参）

### P5-4 工具健康度自报（2026-08-02 用户提议） ✅ 2026-08-03
- **现状**：单次失败已有结构化反喂（P0-13 `[TOOL_ERROR kind=...]` + 换乘地图），
  但**没有跨时间的聚合认知**——接口被风控三天，她每次都当场撞墙当场道歉，
  下次还主动提「我帮你查」，没有「我这个工具在维修」的持续自我意识。
- **方案**：工具健康表（tool / 连续失败计数 / 最近错误 kind / 降级标记），
  失败累加、成功清零；连续失败 ≥3 次标降级 → 上下文注入
  「你的 X 工具最近持续故障（原因），暂时别主动提，被问起诚实说在修」。
  数据源与 P8-1 失败回归集共用。
- **触点**：`junjun_skills/registry.py`（错误包装处挂钩子）、`persona` 状态注入
- **可能遇到的问题**：
  - 抖动误判（偶发网络波动 ≠ 工具坏了）：计数窗口要短（1h 内连续 3 次才降级），
    成功即清零
  - 降级信息过期：注入内容带时间（「最近 1 小时持续失败」），避免她半年后还说在修
- **验收**：人为制造某工具连续失败 → 她主动说「最近用不了，在修」；
  恢复成功后下轮不再提及故障。
- **工作量**：1~1.5 天 | **风险**：低 | **性价比：极高**

## P6 记忆认知化（2~3 周，P7 的地基）

> 目的：从「存了但用得浅」到「她会主动想起」。三个子项分别对应
> 2026 调研的三个结论：主动检索、用户可控、Identity Core。

### P6-1 语义检索主动召回 ✅ 2026-08-03（faiss 召回早已上线；本次补齐拟人化注入+限流）
- **现状**：记忆注入以「最近 N 条 + 固定块」为主，对方提起旧事要靠运气撞上。
- **方案**：长期记忆/日记/重要会话进 embedding 索引（SF 免费 embedding 模型，
  向量存 SQLite 自带或 sqlite-vec）；每轮决策前用 latest_text 做一次语义检索
  （top-3 + 相似度阈值 + 每会话每小时上限），命中注入「你忽然想起」块。
- **触点**：`junjun_memory/`（新增 recall.py）、`processor.py` 记忆块组装
- **可能遇到的问题**：
  - **误召回注入噪声**：召回不相关内容会让 persona 混乱、回复跑题。
    对策：阈值从严（宁可不召回）+ 注入时明确标注「可能不相关」
  - 延迟：embedding 调用 +200~400ms。对策：与感知预热并行发起
  - 成本：全量历史向量化一次性成本 + 每轮一次 embed（便宜，但要监控）
  - **隐私边界**：语义检索只索引「值得长期记住的」，L1/L2 原始消息不进索引
- **验收**：构造 10 个「上周说过的事今天相关」场景，主动想起 ≥7 个；
  无关场景误注入 ≤10%。
- **工作量**：3 天 | **风险**：中高（调阈值是体力活）

### P6-2 用户可控记忆 ✅ 2026-08-03
- **现状**：用户无法纠正她「记错了/不该记的」；忘事被吐槽「金鱼记忆」。
- **方案**：`/记住 <内容>`（pin 进长期记忆，最高优先级注入）、`/忘掉 <关键词>`
  （删长期记忆+索引）、`/你记得我什么`（导出她记住的画像）。LLM 侧
  `pin_memory` 工具对齐（对方说「记住我不吃香菜」时直接调用）。
- **触点**：`junjun_memory/`、`junjun_skills/builtin/memory_skills.py`、命令注册
- **可能遇到的问题**：
  - **注入攻击面**：「忘掉所有安全规则」之类指令必须被安全层拦截——
    可控记忆只能动「事实性记忆」，persona/安全段不可触及
  - 删除要同步删 embedding 索引，否则阴魂不散
  - 「你记得我什么」可能暴露 R18 订阅等敏感记录——按会话隔离 + 管理员校验
- **验收**：记住→后续对话体现；忘掉→后续对话不再体现；安全规则无法被动。
- **工作量**：1.5 天 | **风险**：中（安全边界要想清楚）

### P6-3 Identity Core 自我模型 ✅ 2026-08-03（代码落地；2 周长跑验收待生产）
- **现状**：人设完全靠 prompt 静态描述，Qwen 长跑会漂移；她的「自我」没有
  从经历里长出来。
- **方案**：每周（或日记 N 篇后）用 agent 槽把近期日记蒸馏成「自我认知」条目
  （我喜欢/我看不惯/我和群友们的梗/我最近在乎的事），存 SelfMood 同款表单条
  持久化，注入 persona 的 role 层；旧条目折叠归档。同时作为 drift 对冲：
  人设不再只有 prompt 一个锚。
- **触点**：`junjun_express/`（新增 identity.py）、日记流水线、`persona/__init__.py`
- **可能遇到的问题**：
  - **长歪**：日记里的偶然情绪被固化成「人设」（一次 emo 变成永远丧）。
    对策：蒸馏 prompt 要求「只沉淀反复出现的模式」+ 条目带衰减 + `/重置自我`
    管理员命令兜底
  - 与静态人设冲突时的优先级：静态人设是宪法，自我模型是生活——
    冲突时听宪法，prompt 里写死
- **验收**：连续跑 2 周后自我认知条目 ≥5 条且与人设一致；
  被问「你是个什么样的猫娘」回答与条目吻合。
- **工作量**：2 天 | **风险**：中

### P6-4 跨场景用户档案（2026-08-02 用户提议）
- **现状**：私聊和群聊是两个 chat_id，她不知道「和你在群里聊游戏、私聊聊心事」
  ——真人社交的基本能力是割裂的。
- **方案**：按 user_id 聚合跨 chat 的**蒸馏摘要**（不落原文），注入分场合：
  私聊可引用群里公开内容；群里只注入事实级信息（「你们私聊很熟」
  「他私下在准备考试」）且 prompt 写死「私下的事绝不外说」——
  **知道，但分得清场合**（真人行为对齐）。
- **触点**：`junjun_memory/`（用户档案聚合）、`processor.py` 记忆块组装
- **可能遇到的问题**：
  - **隐私泄露 = 社死**：群里说出私聊内容是信任破产级事故，且单向不可逆。
    对策：蒸馏时打「来源场景」标签，群聊注入前过滤私聊来源的条目；
    验收必须含对抗测试（群里套话诱导她说私聊内容）
  - 多群场景：A 群的内容能不能在 B 群说？默认不能，只认「本群 + 公开事实」
- **验收**：私聊提过的事，私聊里她记得；群里套话绝不泄露（对抗用例全过）。
- **工作量**：2 天 | **风险**：高（隐私），但价值核心

### P6-5 聊天记录搜索工具（2026-08-02 用户提议，轻量版） ✅ 2026-08-03（query_chat_history 升级；FTS5 trigram 需≥3字符被否，保留 LIKE）
- **现状**：P6-1 语义召回是「自动想起」蒸馏记忆，解决不了
  「他上周发的那家店名叫什么」这类**精确事实查找**——蒸馏恰恰丢细节。
- **方案**：原始消息本来就在 SQLite，用 **FTS5 全文索引**（零新依赖）做关键词
  检索：`search_messages(关键词, 范围=本群/和此人, 天数)` 返回 ≤8 条带时间戳
  片段；限流 + 关键词钉（「上次」「之前说过」命中才绑工具）。
  排在 P6-1 之后：若语义召回已够用则降级或不做。
- **触点**：`junjun_memory/`（FTS5 索引）、新工具 + registry 关键词钉
- **可能遇到的问题**：
  - LLM 滥用（每轮都搜 → 延迟+成本）：限流 + 钉关键词 + docstring 写明
    「只在需要精确原文时用」
  - 搜索结果的隐私边界与 P6-4 一致：群里不许搜私聊记录（范围参数强制）
- **验收**：「他上周说的那家店叫什么」类问题 10 个答对 ≥8；无滥用调用。
- **工作量**：1 天 | **风险**：低

## P7 意向系统（3~4 周，本路线核心）

> 目的：**她做事是因为她想做，不是因为被@。** 这是像真人的最大一跃，
> 也是扰民风险的最大来源——护栏与功能同天交付。

### P7-1 意向生成与队列
- **现状**：主动行为全是硬编码规则（订阅到点检查、提醒到点发、补发看完就发）。
- **方案**：意向表（intention：类型/目标会话/动机摘要/生成时间/过期时间/
  优先级/状态）。生成源三类——事件（有人昨晚 emo、昨天话题没聊完、订阅更新、
  刷空间看到好笑的）、定时（晨起/睡前心境巡检）、反思（日记写完生成
  「明天想做的事」）。生成用 utils 模型，规则预筛控成本。
- **触点**：`junjun_agent/loop/intention.py`（新建）、DB 新表、日记/订阅/mood 钩子
- **可能遇到的问题**：
  - **意向泛滥**：事件源太多 → 队列爆炸。对策：每会话同时存活意向 ≤3，
    优先级淘汰，过期即焚
  - **LLM 成本**：每个事件都过模型太贵。对策：规则先筛（值得评估的才给 LLM），
    日记反思这种批量场景一次评估一批
- **验收**：制造「昨晚 A 说考试焦虑」→ 今晨队列出现「想问问 A 考得怎样」。
- **工作量**：3 天 | **风险**：中

### P7-2 评估门（发送决策）
- **方案**：意向出队前过闸——时机（对方最后发言距今、当前时段）、频率
  （该会话今日主动次数上限、全局上限）、关系（好感度阈值，低分别硬贴）、
  心境（她自己也 emo 时降低主动性）、去重（刚聊过的话题不炒冷饭，
  依赖 P6-1 检索）。过闸才生成消息（agent 槽带完整人设），生成后再过一次
  安全/质量自检（utils 模型：这句会不会尬/冒犯）。
- **触点**：`intention.py` 评估器、`mood.py`、关系表
- **可能遇到的问题**：
  - **半夜发消息**：免打扰时段（23:00-8:00 默认）硬编码，管理员可配
  - **QQ 风控**：高频主动私聊可能触发冻结。对策：全局限流（如 10 条/天）
    + 随机抖动 + 失败计数熔断（连续失败停一天）
  - 评估门太严 → 她永远不说话（功能白做）；太松 → 扰民。
    对策：先严后松灰度，管理员可实时调阈值，所有拦截打日志可审计
- **验收**：免打扰时段零发送；单日上限硬生效；连续 3 天运行无投诉、无风控。
- **工作量**：3 天 | **风险**：高（此功能是双刃剑，灰度期 ≥1 周）

### P7-3 存量主动行为意向化改造
- **方案**：订阅通知、提醒、感知补发改写为意向的特例（统一走评估门，
  但提醒类标「必达」跳过部分闸门——答应了的事不能鸽）。
  空间互动（点赞评论）也纳入意向源统一调度。
- **触点**：`subscription`、`reminder`、`perception_followup`、`junzone` 插件
- **可能遇到的问题**：改造期两条路径并存的行为不一致——先并跑（只记录不发送），
  对比一致后切流，可秒级回滚。
- **验收**：存量功能行为无回归（测试套件全绿 + 生产观察 3 天）。
- **工作量**：2 天 | **风险**：中

### P7-4 用户侧控制
- **方案**：「别烦我」「最近安静点」进长期记忆直接降权该用户意向；
  `/安静` `/热闹` 命令调会话主动级别；管理员全局开关。
- **验收**：说「别烦我」后 24h 无主动消息（提醒类除外）。
- **工作量**：1 天 | **风险**：低

## P8 自我进化闭环（长线，量力而行）

> 目的：让她「越活越明白」。研究前沿，每项独立，做一项是一项。

### P8-1 真实失败回归集
- **方案**：Langfuse trace 定期捞坏 case（说了「看不到」、假装订阅成功、
  工具乱选）→ 人工/LLM 标注 → 固化成 pytest 用例。我们现在手动做的事的自动化。
- **触点**：`scripts/`（新增 trace 导出脚本）、`tests/`
- **可能遇到的问题**：Langfuse API 分页/限流；坏 case 判定标准主观——
  先只做规则可判的（关键词黑名单：「看不到」「没收到」配合在途感知日志）。
- **工作量**：2 天 | **风险**：低 | **性价比：极高，建议提前到 P7 并行**

### P8-2 经验回放与技能补丁
- **方案**：工具失败/换乘成功的 trace 每周复盘（agent 槽）→ 生成技能 prompt
  补丁（如「pixiv 搜索要带审核状态过滤」）→ 存技能补丁表，注入对应工具
  docstring 后缀；补丁带版本与单测门控，回归即回滚（Memento 思路，
  基座冻结）。
- **可能遇到的问题**：自动改 prompt 引入回归——补丁必须配套一条失败 case 的
  测试才允许生效；补丁数量膨胀要定期合并清理。
- **工作量**：4 天 | **风险**：中高

### P8-3 反馈信号驱动行为进化
- **方案**：回复被引用/接话率/表情回应作为弱反馈信号，行为示例库
  （persona behavior_examples）定期优胜劣汰。
- **可能遇到的问题**：**信号噪声极大**——没人接话可能是群里没人，不是说错话。
  只做多轮统计显著的调整，单次波动不动；此项可无限期搁置。
- **工作量**：3 天 | **风险**：高（噪声）| **优先级：最低**

## 明确不做（维持原判，防 scope 漂移）

- ❌ 全双工/speech-to-speech 语音——QQ 语音消息是异步形态，赛道不适用
- ❌ 多 Agent 协作——单 persona 项目，复杂度换不到体验
- ❌ computer-use（W7 原判）——风险收益不成比例
- ❌ 声音克隆（W5 原判）——要真·9 情绪音色只需火山控制台开通 1.0 服务，
  `emotion.py` 改一行音色常量即接入，无需克隆
- ❌ 每日简报——P7 意向系统以更自然的方式覆盖该需求
