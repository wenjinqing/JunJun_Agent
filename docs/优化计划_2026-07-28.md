# 君君智能度优化计划（2026-07-28）

目标：更像真人、看到更多内容、功能更完整。
原则：每项独立可交付、独立可回滚；优先「感知盲区」（看不到导致蠢），其次「拟人行为」（看到了但不像人），最后「新能力」。

---

## W1 感知增强——先解决「看不到」（性价比最高）✅ 已全部完成

### P0-1 ✅（2026-07-28 完成）引用消息内容解析
- **现状**：adapter 把 reply 段转成 `Seg(type="reply", data=消息id)`，内容完全丢失。
  群友「引用某条消息抬杠/补充」是高频场景，君君看不到被引用内容 → 答非所问。
- **方案**：adapter 解析 reply 段时调 NapCat `get_msg` 拿原消息文本，
  注入为 `[回复 某人: 原文]` 前缀（复用 forward 展开的截断策略，限 200 字）。
- **触点**：`junjun_adapter_napcat/recv_handler/message_handler.py`
- **工作量**：0.5 天 | **风险**：低（失败降级 [回复某条消息] 占位）

### P0-2 ✅（2026-07-28 完成）@某人 → 真实昵称解析
- **现状**：所有 @ 一律转 `@某人` 占位（防 QQ 号误判断的过度矫正）。
  「@白菜兔 你怎么看」君君不知道说的是谁。
- **方案**：adapter 解析 at 段时查群成员昵称（NapCat `get_group_member_info`，
  带缓存），转 `@白菜兔`；查不到才降级 `@某人`。
- **触点**：`message_handler.py` + 新增成员昵称缓存（dict + TTL）
- **工作量**：0.5 天 | **风险**：低

### P0-3 ✅（2026-07-28 完成）表情包内容理解
- **现状**：sticker 只显示 `[表情]`，君君不知道表情包画的是什么。
- **方案**：复用 VLM 识图管线，对 sticker 做描述并注入上下文
  （`[表情: 猫咪竖大拇指]`）。md5 缓存——同一表情包只描述一次；
  与偷图注册共用描述结果（偷入库时顺带写描述，零额外成本）。
- **触点**：`processor.py`（sticker_urls → vision）、`junjun_memory/vision.py`、`junjun_express/emoji.py`
- **工作量**：1 天 | **风险**：中（VLM 调用频率上升，需并发限流）

### P1-4 ✅（2026-07-28 完成）链接内容感知
- **现状**：群友发文章/新闻链接，君君只看到 URL 字符串。
- **方案**：消息含 http 链接时后台 fetch（MCP fetch 或 httpx）抽正文摘要
  （300 字内），注入上下文 `[链接内容: ...]`；超时/失败静默。
- **触点**：`processor.py` + 复用异步任务管理器
- **工作量**：0.5 天 | **风险**：低

## W2 拟人行为——看到了还要像人 ✅ 已全部完成

### P0-5 ✅（2026-07-28 完成）记忆主动联想（不用 LLM 决定）
- **现状**：长期记忆靠 LLM 主动调 `recall_memory`，GLM-5 经常想不起来调 → 「失忆」。
- **方案**：processor 每轮自动用最新一条消息做 embedding 检索长期记忆
  （top 3，相似度阈值过滤），命中直接注入 memory_block。
  LLM 工具保留作为深挖手段。
- **触点**：`processor.py`、`junjun_memory/long_term.py`
- **工作量**：0.5 天 | **风险**：低（ embedding 不可用降级跳过）

### P0-6 ✅（2026-07-28 完成）情绪连贯性落地
- **现状**：mood 系统存在但只影响措辞，不影响行为。
- **方案**：mood_block 增加行为指令层——心情差时回复更短/不爱用工具/不主动发语音；
  心情好时长回复/更可能配图。以「当前心情倾向」自然语言注入 <state>。
- **触点**：`junjun_express/mood.py`、`persona/__init__.py`
- **工作量**：0.5 天 | **风险**：低

### P1-7 ✅（2026-07-28 完成）回复时机仿真
- **现状**：决策完成立刻回复，永远秒回 → 机器人感。
- **方案**：按回复长度 + 关系值 + 时段计算拟人延迟
  （短回复 1-3s，长回复按「打字速度」折算，上限 15s）；
  已在 postprocess 有逐条 delay，前置一个「看完消息的时间」。
- **触点**：`processor.py` 发送前
- **工作量**：0.5 天 | **风险**：低（配置开关，可关）

### P1-8 ✅（2026-07-28 完成）自我反思 → 私聊管理员（**上轮计划欠账，用户明确要求**）
- **方案**：每 50 轮对话，utils 槽 LLM 自评最近回复质量
  （复读率/答非所问/情绪一致性），生成反思摘要私聊发管理员；
  管理员可回「知道了/以后注意 XX」写入 persona 动态提示。
- **触点**：新增 `junjun_agent/loop/reflection.py` + scheduler 注册
- **工作量**：1 天 | **风险**：低

## W3 能力扩展

### P2-9 视频内容理解（关键帧抽帧）
- **现状**：视频只显示 `[视频]`。
- **方案**：ffmpeg 抽 3 帧 → VLM 逐帧描述 → 合并注入
  `[视频: 一只猫在弹钢琴]`；走异步任务（抽帧慢），大小超限降级占位。
- **触点**：`processor.py`、`vision.py`（ffmpeg 已有）
- **工作量**：1 天 | **风险**：中（大视频下载耗时，需限制 ≤50MB）

### P2-10 语音消息理解（ASR）
- **现状**：语音只显示 `[语音]`。
- **方案**：SiliconFlow FunAudioLLM/SenseVoiceSmall（免费额度）转文字注入。
  record 段 URL → 下载 → ASR → `[语音: 明天一起开黑吗]`。
- **触点**：adapter record 段保留 URL + `vision.py` 同款管线
- **工作量**：1 天 | **风险**：低

### P2-11 多轮任务规划（上轮 P1 欠账）
- **方案**：复杂请求（「搜一下 XX 然后画个配图发空间」）拆步骤执行：
  LangGraph 子图任务链，步骤间用异步任务管理器串联。
- **工作量**：2-3 天 | **风险**：高（GLM-5 function calling 稳定性是瓶颈，建议等换更强模型后再做）
