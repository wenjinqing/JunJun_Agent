# 君君 Agent 严厉审查报告（2026-08-04）

> 触发：用户要求「用最严厉的审查，找出痛点」。
> 方法：三个并行审查员深读 60+ 文件（决策层 / 记忆与上下文 / 工程基建），
> 对照业界标准（Anthropic Building Effective Agents、OpenAI Agents Evals、
> 12-factor agents、context engineering 共识、591 起 agent 生产故障统计）。
> 每条发现均有文件:行号证据（行号为审查当日快照，后续改动可能漂移）。

## 判决

**补丁速度超过架构收敛速度：用 prompt 和正则对冲结构缺陷，且没有任何度量能告诉
你补丁有没有用。** 源码 18 处「实锤/事故/灵异」注释、45 个文件带事故日期标注；
persona rules 几乎每条挂着一起生产事故——rules 列表是事故疤痕墙，且因无 eval
没人敢删，只会变厚（context rot 教科书走法）。

## P0（不修会继续流血）

### P0-1 零 eval 体系：所有改进都是盲改
- Langfuse trace 已全量接通，距业界标配只差一个标注数据集——但这个差是致命的。
- 决策层任何改动（prompt 规则/换模型/掩码阈值）都可能让关键路径悄悄退化，
  唯一发现渠道是用户被骂醒。
- 1268 个测试全是单测 + 事故回归锁（`test_p0_fixes.py` 等文件名即证词），
  agent 链路「消息进→回复出」零端到端覆盖；仅 13 个文件 mock LLM，
  真实模型怪癖类 bug（如 `_relax_str_args`）结构性复现不了。

### P0-2 决策漏斗名存实亡，还在空转烧钱
- `processor.py` 实际决策门只剩 `is_addressed()`；`rule_gate()`/`llm_gate()`
  生产路径从未被调用（仅 tests 引用）。
- `frequency.py` 每 160s/20 条烧一次 LLM 更新无人消费的 `adjust_factor`；
  WebUI 上对应配置项是假开关。文档仍宣称「三级漏斗」在运行。

### P0-3 上下文是一坨纯文本：bot 的话以 user 身份喂回模型
- 全部历史拼成一个 HumanMessage，bot 发言以 `你(历史): xxx` 文本前缀混在
  user role 里（`agent.py`、`junjun_memory/short_term.py`）。
- 入站消息无条件 `add_user`，`is_self` 过滤发生在记忆写入之后
  （`processor.py`）——系统亲手把 bot 的话伪装成别人说的喂回去。
- 后果：四层 echo 补丁交利息（渲染去重、出口拦截+整轮重跑、口头禅黑名单、
  模板池军备竞赛）。业界做法（AIMessage 轮次）一次性还清本金。

### P0-4 隐私边界靠 prompt 自觉，还有一个明摆着的洞
- `recall_memory` 本会话搜不到就放宽全库再搜——A 群可套出私聊记忆。
- 私聊素材进日记后以 `self:diary` 入向量库，任何群聊会话召回域都包含日记；
  防泄露只靠 rules 里一句「别逐字念」。
- 对照组：`scene_profile.py` 已在数据结构层强制隔离（「隐私生命线」注释），
  长期记忆没跟上。

### P0-5 两套任务系统语义打架 + 两条出站路径护栏全漏
- TaskManager（内存+JSONL）把重启孤儿标失败；AsyncJob（SQLite）回炉重跑。
  优雅 shutdown 不写 end 记录 → 正常重启也被记成「任务中断」。
- 后台任务直发 `gateway.send_reply` 绕过主管线（分条/echo guard/R18 打码/限流
  全部失效）。「图呢」「一直说还在画」两次幻觉都源于这条裂缝。
  订阅推送、junzone 发帖、fun_texts 同走裸发路径。

## P1（真 bug / 高隐患）

### P1-6 意图 nudge first-match 短路 + 拦截器双决策权威
- 「提醒我明天开会，顺便画一只猫」：reminder 组先命中且已调用即 `return None`，
  ai_draw 没调也永不追问（`agent.py`）。关键词裸 substring：单字「盯」误命中
  「他老盯着我看」。
- nsfw_draw 正则 `(画|生成)[^\n]{0,30}(涩|色的)` 劫持「画一张蓝色的天空」；
  复合消息后半句静默丢失；拦截器回复不写记忆不过 echo guard（正在制造
  昨天刚修过的那类幻觉）；匹配优先级 = 插件目录字母序。

### P1-7 会话队列 drain 静默吞命令
- `session_queue.py` 合并队列只对最新一条触发决策，但命令总线/拦截器/管理员
  指令都在决策段——「/sub add xxx」+「你在吗」连发，斜杠命令静默丢弃零日志。

### P1-8 单写队列纪律名存实亡
- `db_writer.submit` 全仓仅 5 处调用；`async_jobs.py` 原子认领等大量同步
  peewee 写裸奔在事件循环上——SQLite 一次卡顿全 bot 停转。同一模块两套写法
  并存。踩坑清单自己立的规矩只覆盖了 5 个点。

## P2（结构性欠债）

### P2-9 零 token 预算，十几个上下文块无脑拼接
- `_build_memory_block` 无差别 append 十几块（钉住 50 条全注），再叠 relation/
  expression/mood/health/skills——全仓无 token 计数；独立 I/O 串行 await，
  决策延迟是各块之和。`build_system_prompt` 为 Langfuse 快照每轮构建两次。
- `<state>` 块用单空格 join 多行块，块边界粘连。

### P2-10 记忆检索与遗忘都是半坏的
- 向量阈值 0.3 形同虚设（bge-m3 不相关中文也有 0.4~0.6）；
  `weight` 只用于遗忘不进检索排序；`add()` 无查重（同一事实 N 份挤占 top-3）；
  「90天+低权重」遗忘口永不触发（weight 无衰减），退化为 5000 条 FIFO；
  每次 `add()` 全量重写 faiss+JSON+双 .bak（同步 IO 跑在 async 里，O(n²) 写放大）。

## 次要观察
- 会话工具快照陈旧：MCP 工具注册后已建会话 3 天内看不到。
- registry 只兜异常不设超时；health 只提示不熔断。
- 45+ 处 env 直读无密钥注册表；ADMIN_QQ 单一信任根无审计落库。
- echo 重说判定只查整句不查口头禅；`max_agent_iterations` 配置放错段（[memory]）。
- detect_complexity 单字「先/再/写/查」误报率高（「再见」「再也不」全中）。
- agent 从渲染后字符串启发式反推「最新消息」，与 meta.text 两条真相路径。

## 公道话
单点工艺有品位：写队列看门狗、网关 token 强制、str 参数宽松化、错误五分类、
scene_profile 结构化隔离、否定证据注入、任务结局持久化。问题不在手艺，在
**没有收敛机制**——每次事故以最小代价灭火，没有 eval 逼问根因。

## 处方（按止血顺序）
1. **Golden dataset 先行**：Langfuse trace 捞 30-50 条真实 case，轨迹评分挂 CI。
2. P0-2 漏斗二选一（删或接）。
3. 出站统一管线：所有主动发送走主管线后处理 + 记忆回填。
4. 隐私收口：MemoryItem 加 scope，search 强制场景过滤，杀全库 fallback。
5. 上下文 role 结构化（私聊先行）：bot 历史改 AIMessage，逐层下线 echo 补丁。
6. 真 bug 包：nudge first-match、drain 吞命令、shutdown 假中断。
7. ContextBudget：每块申报 token+优先级；独立 I/O 改 gather。
